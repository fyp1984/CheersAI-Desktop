## 快速诊断

### 1. 检查文档状态统计

**脚本**: `check_status_counts.py`

**用途**: 快速查看知识库中各状态文档的数量

**使用方法**:
```bash
cd api
python check_status_counts.py
```

**输出示例**:
```
Document status counts:
  completed: 5
  error: 2
  waiting: 1
  indexing: 0
```

**状态说明**:
- `waiting`: 等待处理
- `indexing`: 正在处理
- `completed`: 处理成功
- `error`: 处理失败

---

### 2. 查看所有文档详情

**脚本**: `check_doc_details.py`

**用途**: 查看知识库中所有文档的名称、状态和创建时间

**使用方法**:
```bash
cd api
python check_doc_details.py
```

**输出示例**:
```
All documents:
  - 用户手册.pdf: completed (created: 2026-04-08 13:16:33)
  - 产品介绍.md: error (created: 2026-04-08 13:16:08)
  - API文档.md: completed (created: 2026-04-08 13:03:50)
```

## 详细检查

### 3. 检查错误文档详情

**脚本**: `check_all_docs_status.py`

**用途**: 使用 Flask 应用上下文查看文档状态，包含详细的错误信息

**使用方法**:
```bash
cd api
python check_all_docs_status.py
```

**输出示例**:
```
Document status summary:
  completed: 5
  error: 2

Recent error documents:
  - 产品介绍.md
    Error: An error occurred in the langgenius/dify_extractor/dify_extractor...
    Created: 2026-04-08 13:16:08
```

**注意**: 此脚本需要加载完整的 Flask 应用，启动时间较长（约 5-10 秒）

---

### 4. 检查成功文档的处理方式

**脚本**: `check_successful_doc.py`

**用途**: 查看成功处理的文档使用了什么处理方式

**使用方法**:
```bash
cd api
python check_successful_doc.py
```

**输出示例**:
```
Successful document:
  Name: API文档.md
  Status: completed
  Data source type: local_file
  Doc form: text_model
  Created: 2026-04-08 13:03:50
```

**字段说明**:
- `Data source type`: 数据源类型（local_file, upload_file 等）
- `Doc form`: 文档形式（text_model, qa_model 等）

## 问题修复

### 5. 重置错误文档

**脚本**: `reset_all_errors.py`

**用途**: 将所有错误状态的文档重置为等待状态，以便重新处理

**使用方法**:
```bash
cd api
python reset_all_errors.py
```

**输出示例**:
```
Found 2 error documents
Reset 2 documents to waiting status

请在知识库界面点击"重新索引"按钮来触发处理
```

**重要提示**:
- 此脚本只是重置状态，不会自动触发处理
- 重置后需要在 Web 界面手动点击"重新索引"按钮
- 或者等待自动修复任务（每 2 分钟运行一次）

---

### 6. 自动修复任务

**脚本**: `schedule/auto_fix_documents_process_rule.py`

**用途**: 定时任务，自动修复缺少 `dataset_process_rule_id` 的文档

**运行方式**: 由 Celery Beat 自动调度，每 2 分钟运行一次

**查看日志**:
```bash
# 查看 Celery Worker 日志
docker logs -f <celery_worker_container>

# 或在本地运行时查看终端输出
```

**日志示例**:
```
Starting auto-fix documents process rule task
Found 3 documents without process rule
Fixed 3 documents for dataset xxx with process rule yyy
Triggered indexing for 3 documents
```

### 8. 重启服务

**重启 Plugin Daemon**:
```bash
cd docker
docker-compose -f docker-compose.middleware.yaml restart plugin_daemon
```

**重启 Unstructured API**:
```bash
cd docker
docker-compose -f docker-compose.middleware.yaml restart unstructured
```

**重启 Flask API**:
```bash
# 如果使用进程管理器，停止并重新启动
# 或者直接 Ctrl+C 然后重新运行
cd api
python -m uv run flask run --host 0.0.0.0 --port=5001 --debug
```

**重启 Celery Worker**:
```bash
cd api
python -m uv run celery -A app.celery worker -P gevent -c 1 --loglevel INFO \
  -Q dataset,priority_dataset,pipeline,priority_pipeline,generation,mail,ops_trace,app_deletion
```

## 常见问题

### Q1: 文档一直处于 "waiting" 状态

**可能原因**:
1. Celery Worker 未运行或未监听正确的队列
2. 文档缺少 `dataset_process_rule_id`

**解决方法**:
```bash
# 1. 检查 Celery Worker 是否运行
ps aux | grep celery

# 2. 运行自动修复脚本
cd api
python reset_all_errors.py

# 3. 在 Web 界面点击"重新索引"
```

---

### Q2: 文档处理失败，错误信息为 "Connection refused"

**可能原因**:
1. Unstructured API 服务未运行
2. Plugin Daemon 无法访问 Unstructured 服务
3. 网络配置问题

**解决方法**:
```bash
# 1. 检查 Unstructured 服务
docker ps | grep unstructured
curl http://localhost:8000/healthcheck

# 2. 检查 Plugin Daemon 网络连接
docker exec docker-plugin_daemon-1 curl -f http://unstructured:8000/healthcheck

# 3. 检查环境变量
docker exec docker-plugin_daemon-1 env | grep UNSTRUCTURED

# 4. 如果配置有问题，重启服务
cd docker
docker-compose -f docker-compose.middleware.yaml restart plugin_daemon unstructured
```

---

### Q3: 如何查看详细的错误日志

**Celery Worker 日志**:
```bash
# 如果在终端运行，直接查看输出
# 如果在后台运行，查看日志文件或使用进程管理器

# 查看最近的错误
grep -i "error" celery.log | tail -20
```

**Plugin Daemon 日志**:
```bash
docker logs docker-plugin_daemon-1 --tail 100 | grep -i error
```

**Flask API 日志**:
```bash
# 查看终端输出或日志文件
tail -f api/logs/flask.log
```

---

### Q4: 如何手动触发文档索引

**方法 1: 通过 Web 界面**
1. 进入知识库页面
2. 找到需要重新处理的文档
3. 点击"重新索引"按钮

**方法 2: 通过脚本**
```bash
cd api
python reset_all_errors.py
# 然后在 Web 界面点击"重新索引"
```

**方法 3: 通过数据库**
```sql
-- 重置特定文档状态
UPDATE documents 
SET indexing_status = 'waiting', 
    error = NULL, 
    updated_at = NOW()
WHERE id = '<document_id>';
```

---

### Q5: 自动修复任务不工作

**检查步骤**:
```bash
# 1. 确认 Celery Beat 正在运行
ps aux | grep "celery.*beat"

# 2. 检查 Celery Beat 日志
# 查看是否有调度记录

# 3. 手动运行自动修复任务
cd api
python -c "from schedule.auto_fix_documents_process_rule import auto_fix_documents_process_rule_task; auto_fix_documents_process_rule_task()"
```

## 最佳实践

1. **定期检查**: 每天运行 `check_status_counts.py` 查看文档处理情况
2. **错误处理**: 发现错误文档时，先运行 `check_all_docs_status.py` 查看详细错误信息
3. **批量修复**: 使用 `reset_all_errors.py` 批量重置错误文档
4. **监控日志**: 定期查看 Celery Worker 和 Plugin Daemon 日志
5. **备份数据**: 在执行修复操作前，建议备份数据库

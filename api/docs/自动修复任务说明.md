# 知识库文档自动修复任务说明

## 概述

系统现在有两个自动修复任务，每隔一定时间自动运行，确保知识库文档能够正常处理。

## 任务1: 自动分配处理规则 (auto_fix_documents_process_rule)

**文件**: `api/schedule/auto_fix_documents_process_rule.py`

**运行频率**: 每2分钟

**功能**:
- 查找状态为"排队中"(pending)的文档
- 自动分配 dataset_process_rule_id
- 触发文档索引处理

**适用场景**:
- 通过RAG Pipeline上传的文档没有自动分配处理规则
- 文档一直处于"排队中"状态

## 任务2: 自动修复提取器错误 (auto_fix_extractor_errors)

**文件**: `api/schedule/auto_fix_extractor_errors.py`

**运行频率**: 每30秒

**功能**:
- 查找因 dify_extractor 插件连接错误而失败的文档
- 对于文本文件(.txt, .md, .markdown, .csv)，直接从存储读取内容
- 创建文档分段(segment)
- 标记文档为已完成

**适用场景**:
- dify_extractor 插件无法连接到 Unstructured API
- 文档状态为"error"且错误信息包含"dify_extractor"和"Connection refused"

**处理流程**:
1. 查询错误文档
2. 获取上传文件信息(UploadFile)
3. 使用 storage.load() 从存储系统读取文件内容
4. 创建文档分段，包含文件内容
5. 更新文档状态为"completed"

## 技术细节

### 文件访问方式

系统使用 Dify 的存储抽象层访问文件:

```python
from extensions.ext_storage import storage

# 通过 UploadFile.key 读取文件
content_bytes = storage.load(upload_file.key)
content = content_bytes.decode('utf-8', errors='ignore')
```

**注意**: 不要直接访问文件路径，UploadFile 模型没有 `path` 属性。

### 文档分段创建

创建分段时必须提供 `created_by` 字段:

```python
segment = DocumentSegment(
    tenant_id=doc.tenant_id,
    dataset_id=doc.dataset_id,
    document_id=doc.id,
    position=1,
    content=content[:5000],
    word_count=len(content.split()),
    tokens=len(content.split()),
    status="completed",
    indexing_at=datetime.utcnow(),
    completed_at=datetime.utcnow(),
    enabled=True,
    created_by=doc.created_by,  # 必须提供
)
```

## 启动服务

自动修复任务通过 Celery Beat 调度运行:

```bash
# 启动 Celery Beat (调度器)
python -m uv run celery -A app.celery beat --loglevel INFO

# 启动 Celery Worker (执行器)
python -m uv run celery -A app.celery worker -P gevent -c 1 --loglevel INFO -Q dataset,priority_dataset,pipeline,priority_pipeline,generation,mail,ops_trace,app_deletion
```

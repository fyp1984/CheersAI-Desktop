# SSO 登录 500 错误 - 完整修复总结

## 问题历程

### 初始问题
用户在 SSO 登录时遇到 500 INTERNAL SERVER ERROR。

### 发现的问题

#### 问题 1: `custom_config_dict` 属性访问错误 ✅ 已修复

**文件**: `api/controllers/console/auth/desktop_sso.py`

```python
# ❌ 错误的代码
custom_config = account.custom_config_dict if account.custom_config else {}

# ✅ 修复后
custom_config = account.custom_config_dict
```

**原因**: `custom_config_dict` 属性已经处理了 `None` 的情况，不需要额外检查。

#### 问题 2: 保存配置时使用错误的属性 ✅ 已修复

**文件**: `api/services/filebay_config_service.py`

```python
# ❌ 错误的代码
account.custom_config = config  # 直接赋值字典给 JSON 字段

# ✅ 修复后
account.custom_config_dict = config  # 使用属性 setter
```

**原因**: `custom_config` 是 JSON 字符串字段，必须使用 `custom_config_dict` setter。

#### 问题 3: Redis 端口配置错误 ✅ 已修复

**根本原因**: Docker Compose 将 Redis 映射到主机的 6700 端口，但 `.env` 配置使用了 6379。

**Docker Compose 配置**:
```yaml
redis:
  ports:
    - "6700:6379"  # 主机 6700 → 容器 6379
```

**修复**: 修改 `api/.env`
```env
REDIS_PORT=6700  # ✅ 使用正确的端口
CELERY_BROKER_URL=redis://:difyai123456@127.0.0.1:6700/1
```

#### 问题 4: 旧 Redis 容器干扰 ✅ 已修复

**发现**: 系统中有两个 Redis 容器在运行
- `dify-redis`：正确的容器（端口 6700）
- `dify-redis-1`：旧容器（无端口映射）

**修复**: 停止并删除旧容器
```bash
docker stop dify-redis-1
docker rm dify-redis-1
```

## 技术要点

### Account.custom_config_dict 属性

```python
@property
def custom_config_dict(self) -> dict[str, Any]:
    return json.loads(self.custom_config) if self.custom_config else {}

@custom_config_dict.setter
def custom_config_dict(self, value: dict[str, Any]) -> None:
    self.custom_config = json.dumps(value)
```

**使用规则**:
- ✅ 始终使用 `custom_config_dict` 属性
- ❌ 不要直接访问 `custom_config` 字段
- ✅ Getter 自动处理 `None` 情况
- ✅ Setter 自动序列化为 JSON

### Docker 端口映射

```yaml
ports:
  - "主机端口:容器端口"
```

**示例**:
- `6700:6379` → 主机访问 6700，容器内部 6379
- Flask 连接 `127.0.0.1:6700`
- 容器内服务连接 `redis:6379`

## 1. 项目概述

### 1.1 项目背景

CheersAI-Desktop 已进入团队版阶段，需要根据三类用户角色（管理员、编辑、成员）优化菜单结构和用户体验。当前系统需强化以下核心原则：

1. **本地安全优先**：文件脱敏、反脱敏功能必须在本地Vault客户端完成，脱敏后文件通过FileBay同步API上传至FileBay服务端；云端AI服务访问文件时，从FileBay的文件服务器访问文件
2. **用户体验至上**：用户登录后首页即展示常用Agent列表，支持一键使用；Agent使用中如需调用文件，智能引导用户前往脱敏沙箱进行文件脱敏，处理后返回Agent工作页面
3. **角色权限清晰**：三类角色权限分明，避免功能混淆
4. **入口明确**：Vault功能以客户端右侧边缘的侧边栏图标按钮方式提供用户入口，用户可随时点击从Desktop返回Vault进行文件脱敏、同步和反脱敏操作

### 1.2 项目目标

**核心目标**: 在保持系统架构不变的前提下，优化菜单结构和用户体验，实现：
- ✅ **角色化菜单**：根据管理员、编辑、成员显示不同功能入口
- ✅ **Vault入口优化**：Vault作为右侧边缘浮动图标按钮，用户可随时点击返回Vault操作
- ✅ **Agent中心化**：首页聚焦常用Agent，脱敏流程智能引导
- ✅ **文件流清晰化**：本地脱敏 → FileBay同步 → 云端访问的完整流程
- ✅ **权限精细化**：成员和编辑角色仅能设置个人客户端功能，管理员拥有全功能设置权限

### 1.3 项目范围

**包含**:
- 菜单结构根据角色权限重组
- Vault浮动图标按钮设计（客户端右侧边缘）
- Agent使用流程与脱敏流程整合
- 三类角色的权限定义与界面适配

**不包含**:
- 功能删减或新增
- 后端API重构
- 数据库结构变更
- Vault/FileBay核心功能修改

## 2. 产品定位

### 2.1 产品愿景

**为团队提供安全、高效、易用的AI协作平台，以本地数据安全为基石，让AI助手赋能每个角色**

### 2.2 目标用户（团队版）

| 用户角色 | 占比 | 核心需求 | 关键权限 |
|---------|------|---------|---------|
| **成员** | 60% | 快速使用Agent完成任务 | 仅使用Agent和对话 |
| **编辑** | 30% | 创建和管理智能体 | 创建/编辑应用，管理智能体 |
| **管理员** | 10% | 团队管理和合规控制 | 全功能权限+团队管理 |

### 2.3 核心原则

#### 原则 1: 本地安全优先
- **所有敏感数据处理在本地Vault客户端完成**，脱敏/反脱敏操作不离开用户设备
- 脱敏后文件通过**FileBay API同步到云端FileBay服务端**
- 云端AI服务从**FileBay服务器访问文件**
- 原始数据和映射表永不离开本地设备

#### 原则 2: Agent为中心
- 首页默认显示用户**常用Agent**，支持一键使用
- 所有功能围绕Agent使用场景设计
- Agent使用中如需调用文件，**智能引导用户前往脱敏沙箱**进行文件脱敏，处理后返回Agent工作页面

#### 原则 3: 角色化体验
- 菜单和功能根据角色动态显示
- 避免权限混淆，减少用户困惑
- 渐进式功能披露，按需展示

#### 原则 4: Vault入口清晰
- Vault功能入口为**客户端右侧边缘的侧边栏图标按钮**
- 用户可随时点击从Desktop返回Vault进行文件脱敏、同步和反脱敏操作
- 非主菜单项，保持界面简洁

## 3. 现状分析

### 3.1 当前菜单结构（v1.0参考）

#### 主菜单（侧边栏）
1. **我的 Agent** (`/agents`) - 首页/默认
2. **对话** (`/chat`)
3. **数据安全** (`/security`) - 简化版
4. **知识库** (`/datasets`)
5. **工具与插件** (`/tools-plugins`) - 合并
6. **探索** (`/explore`)
7. **审计日志** (`/audit-logs`) - 管理员可见

### 3.2 问题诊断（基于新要求）

#### 问题 1: Vault入口不明确
- **现象**: Vault作为独立功能模块，未与Agent流程深度整合
- **影响**: 用户需要手动切换页面进行文件脱敏
- **要求**: Vault应作为**侧边栏图标按钮**，位于客户端右侧边缘，而非主菜单项

#### 问题 2: 角色权限未体现
- **现象**: 所有用户看到相同的菜单结构
- **影响**: 成员用户看到不相关的功能，造成困惑
- **要求**: 根据管理员、编辑、成员显示不同菜单

#### 问题 3: 文件流不清晰
- **现象**: 用户不清楚文件脱敏后的同步路径
- **影响**: 对数据安全流程缺乏信任感
- **要求**: 明确"**本地Vault脱敏 → FileBay API上传 → 云端AI从FileBay服务器访问**"的完整路径

#### 问题 4: 首页Agent不突出
- **现象**: 虽然"我的Agent"是首页，但常用Agent未优先展示
- **影响**: 用户需要多次点击才能找到常用功能
- **要求**: 首页默认展示常用Agent，智能排序

#### 问题 5: 系统设置权限混淆
- **现象**: 所有角色都有系统设置入口
- **影响**: 成员和编辑误以为可以修改团队设置
- **要求**: 明确**成员和编辑只能设置个人客户端功能**，管理员拥有全功能设置权限

### 3.3 架构约束

#### 必须遵守的技术架构
```
用户操作流程:
1. 用户上传文件 → **本地Vault客户端脱敏**（必须本地完成）
2. 脱敏后文件 → **通过FileBay API同步到云端FileBay服务器**
3. 云端AI服务 → **从FileBay服务器读取脱敏文件**
4. AI处理结果 → 返回给用户
5. 需要还原时 → **本地Vault客户端反脱敏**（必须本地完成）

关键约束:
- Vault: 本地客户端组件，通过IPC与Desktop通信
- FileBay: 基于Gitea的云端文件同步服务
- 映射表: 永远保留在本地加密沙箱，不上传云端
- **Vault入口**: 客户端右侧边缘的侧边栏图标按钮，非主菜单项
```

## 4. 优化目标

### 4.1 核心目标

| 目标 | 当前状态 | 目标状态 | 衡量指标 |
|------|--------|--------|---------|
| **角色适配度** | 统一菜单 | 角色化菜单 | 不同角色看到不同菜单项 |
| **Vault集成度** | 独立菜单项 | **侧边栏图标按钮** | Vault入口直观易用 |
| **Agent访问效率** | 首页显示 | 常用Agent优先 | 常用Agent一键访问 |
| **文件脱敏流程** | 手动切换 | 智能引导 | 脱敏提示自动触发 |
| **用户困惑度** | 高 | 低 | 角色权限混淆率<5% |
| **系统设置权限** | 混淆 | 清晰分层 | 成员/编辑仅个人设置，管理员全权限 |

### 4.2 设计原则

#### 原则 1: 角色适配（Role-Adaptive）
- 菜单和功能根据用户角色动态显示
- 隐藏无权限的功能，减少认知负担
- 权限变更时界面即时更新

#### 原则 2: 渐进披露（Progressive Disclosure）
- 默认显示核心功能（Agent+对话）
- 高级功能按需展开
- 通过使用频率智能排序

#### 原则 3: 流程连贯（Seamless Flow）
- Agent使用与文件脱敏流程无缝衔接
- 智能检测敏感数据，主动提示
- 减少页面跳转，保持上下文

#### 原则 4: 本地优先（Local-First）
- 强调**本地Vault客户端完成脱敏/反脱敏**的安全性
- 明确标识"本地脱敏"、"FileBay同步"、"云端AI访问"等状态
- 建立用户对数据安全的信任感

#### 原则 5: 入口明确（Clear Entry）
- **Vault入口为右侧边缘侧边栏图标按钮**
- 用户可随时点击从Desktop返回Vault操作
- 保持界面简洁，非主菜单项

## 5. 团队角色与权限设计

### 5.1 角色定义

| 角色 | 英文标识 | 描述 | 典型用户 |
|------|---------|------|---------|
| **管理员** | `admin` | 团队管理者，拥有全部权限 | 团队负责人、IT管理员 |
| **编辑** | `editor` | 内容创作者，可创建和管理智能体 | 产品经理、业务专家 |
| **成员** | `member` | 普通使用者，仅使用现有功能 | 业务人员、普通员工 |

### 5.2 权限矩阵

| 功能模块        | 成员    | 编辑      | 管理员        |
| ----------- | ----- | ------- | ---------- |
| **Agent使用** | ✅ 仅使用 | ✅ 使用+创建 | ✅ 使用+创建+管理 |
| **对话应用**    | ✅     | ✅       | ✅          |
| **知识库**     | ✅ 仅查看 | ✅ 查看+上传 | ✅ 全权限      |
| **智能体管理**   | ❌     | ✅ 管理智能体 | ✅ 全权限      |
| **工作流编排**   | ❌     | ✅ 使用现有  | ✅ 创建+管理    |
| **应用创建**    | ❌     | ✅ 创建应用  | ✅ 创建+管理    |
| **模型配置**    | ❌     | ❌       | ✅ 配置大模型服务  |
| **团队管理**    | ❌     | ❌       | ✅ 成员/角色管理  |
| **审计日志**    | ❌     | ❌       | ✅ 查看+导出    |
| **系统设置**    | ✅ **个人客户端设置** | ✅ **个人客户端设置** | ✅ **全权限**      |

**系统设置权限说明**：
- **成员 & 编辑**：仅可设置个人客户端功能（语言、开机自启动、外观、邮箱、手机号、快捷键等）
- **管理员**：拥有全部系统设置权限（个人客户端设置 + 团队级设置 + 系统级配置）

### 5.3 权限详细说明

#### 5.3.1 成员（Member）
**核心权限**：使用现有Agent完成任务
- 使用团队共享的Agent
- 使用对话应用
- 查看知识库文档
- 查看团队公开信息
- **个人系统设置**：语言、开机自启动、外观、邮箱、手机号、快捷键等个人客户端功能

**限制**：
- 不能创建新的Agent或应用
- 不能修改团队设置
- 不能访问审计日志
- 不能配置系统级设置

#### 5.3.2 编辑（Editor）
**核心权限**：创建和管理智能体内容
- 所有成员权限
- 创建新的Agent
- 编辑现有Agent
- 上传文档到知识库
- 使用工作流模板
- 创建新的应用
- **个人系统设置**：语言、开机自启动、外观、邮箱、手机号、快捷键等个人客户端功能

**限制**：
- **不能管理团队设置**
- 不能配置大模型服务
- 不能访问审计日志
- 不能配置系统级设置

#### 5.3.3 管理员（Admin）
**核心权限**：团队全面管理
- 所有编辑权限
- 团队成员管理
- 角色权限分配
- 大模型服务配置
- 审计日志查看
- **全功能系统设置**：个人客户端设置 + 团队级设置 + 系统级配置
- 团队数据导出

### 6.4 菜单权限控制逻辑

```typescript
// 权限检查逻辑示例
function getVisibleMenuItems(userRole: 'admin' | 'editor' | 'member') {
  const allItems = [
    { id: 'agents', visible: true },
    { id: 'chat', visible: true },
    { id: 'datasets', visible: true },
    { id: 'agents-manage', visible: ['editor', 'admin'] },
    { id: 'workflows', visible: ['editor', 'admin'] },
    { id: 'apps', visible: ['editor', 'admin'] },
    { id: 'team-settings', visible: ['admin'] },
    { id: 'audit-logs', visible: ['admin'] },
    { id: 'explore', visible: true, optional: true },
    { id: 'settings', visible: true, optional: true }
  ];
  
  return allItems.filter(item => {
    if (item.visible === true) return true;
    if (Array.isArray(item.visible)) return item.visible.includes(userRole);
    return false;
  });
}
```

## 14. 附录

### 14.1 术语表

| 术语 | 说明 |
|------|------|
| **Vault** | CheersAI本地文件脱敏安全屋，**负责本地敏感数据处理** |
| **FileBay** | 基于Gitea的脱敏文件同步服务，**云端文件服务器** |
| **成员 (Member)** | 团队普通用户，仅可使用现有功能 |
| **编辑 (Editor)** | 团队内容创作者，可创建和管理智能体，**不能管理团队设置** |
| **管理员 (Admin)** | 团队管理者，拥有全部权限 |
| **智能体 (Agent)** | AI智能体，可执行特定任务 |
| **映射表** | 原始数据与脱敏数据的对应关系表，**本地加密存储** |

### 14.2 文件流架构图

```
用户操作层
    ↓
CheersAI Desktop客户端
    ├─ 界面交互
    ├─ 权限控制
    └─ 流程协调
    ↓
**本地处理层**
    ├─ **Vault客户端 (本地脱敏/还原)**
    ├─ 加密沙箱 (原始数据存储)
    └─ 映射表加密存储
    ↓
**云端同步层**
    ├─ **FileBay服务端 (Gitea)**
    ├─ 用户隔离仓库
    └─ 脱敏文件存储
    ↓
AI服务层
    ├─ Dify服务端
    ├─ 模型调用
    └─ **从FileBay服务器读取文件**
```

### 14.3 权限决策流程图

```
用户访问功能
    ↓
检查用户角色 (admin/editor/member)
    ↓
查询功能所需权限
    ↓
检查用户是否有所需权限
    ├─ 有权限 → 允许访问
    └─ 无权限 → 
        ├─ 显示权限提示
        ├─ 提供升级引导
        └─ 阻止操作
```

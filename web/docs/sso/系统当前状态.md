## 系统功能状态

### ✅ 已完成并验证

1. **后端角色提取和映射** (`api/controllers/console/auth/desktop_sso.py`)
   - 从 SSO userinfo 提取角色信息（支持 `type` 和 `role` 字段）
   - 角色映射：admin/owner → owner, technician/editor → editor, 其他 → normal
   - 新用户自动创建并分配角色
   - 现有用户登录时自动更新角色
   - 测试模式：基于用户名自动分配角色（方便测试）

2. **前端菜单权限控制** (`web/app/components/header/side-nav/index.tsx`)
   - 管理员（owner/admin）：8个菜单
   - 技术员（editor）：7个菜单（无审计日志）
   - 普通用户（normal）：5个菜单（无智能体管理、工作流、审计日志）
   - 知识库和应用中心对所有角色可见（普通用户只读）

3. **SSO 登录流程** (`web/service/sso.ts`, `web/app/api/auth/sso/token/route.ts`)
   - OAuth 授权码交换
   - 用户信息获取
   - 后端登录和 Cookie 设置

## 测试模式说明

当前系统使用测试模式进行角色分配，方便本地开发和测试：

```python
# 测试模式：根据用户名自动分配角色
if not sso_role or sso_role == 'user':
    normalized_name = name.lower() if name else ''
    if 'admin' in normalized_email or 'admin' in normalized_name:
        sso_role = 'admin'
    elif 'tech' in normalized_email or 'tech' in normalized_name:
        sso_role = 'technician'
    else:
        sso_role = 'user'
```

**生产环境部署前需要**：
1. 配置 Casdoor 返回真实的 `type` 或 `role` 字段
2. 移除测试模式代码
3. 设置 `TEST_MODE_ALLOW_OWNER_DOWNGRADE = False`

## 已知问题

### 1. Admin 账户 SSO 登录失败
- **问题**: Cookie 大小超过 4096 字符限制
- **原因**: SSO token 或 session 数据过大
- **临时方案**: 使用邮箱密码登录
- **长期方案**: 
  - 优化 Cookie 存储策略
  - 使用 Session Storage 或 Redis 存储大数据
  - 减少 token 中的冗余信息

### 2. 测试模式依赖用户名
- **问题**: 需要用户名包含特定关键字才能自动分配角色
- **影响**: 仅影响测试环境
- **解决方案**: 生产环境配置 Casdoor 返回真实角色字段

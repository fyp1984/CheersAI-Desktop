# SSO Cookie 大小问题修复完成

## 修复内容

已成功修复 admin 账号无法通过 SSO 登录的问题。问题原因是 Casdoor 返回的 access_token 过大（>4096 字符），导致浏览器拒绝设置 cookie。

## 解决方案

采用服务端会话存储：
- Cookie 中只存储小型会话 ID（约 30-40 字符）
- 实际的 access_token 存储在服务器内存中
- 完全解决 cookie 大小限制问题

## 测试步骤

### 1. 重启前端服务

```bash
cd web
npm run dev
```

### 2. 清除浏览器数据

- 打开浏览器开发者工具（F12）
- Application → Cookies → 删除所有 localhost:3000 的 cookies
- 或者使用无痕模式

### 3. 测试 Admin 账号登录

1. 访问：http://localhost:3000/signin
2. 点击 "SSO 登录" 按钮
3. 使用 admin 账号登录：
   - Email: admin@example.com
   - Name: 系统管理员
4. 检查浏览器控制台：
   - 应该看到 `[SSO] Token stored in session: sso_xxx...`
   - 不应该有 Cookie 大小警告
5. 验证登录成功，能看到所有 8 个菜单（包括审计日志）

### 4. 测试其他账号

- Tech 账号（6c6u33@example.com）- 应该看到 7 个菜单（无审计日志）
- 普通用户 - 应该看到 5 个菜单

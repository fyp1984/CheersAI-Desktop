# 测试 FileBay 文件选择器

## ✅ 修复完成

已成功修复 FileBay 文件选择器的 500 错误问题：

1. ✅ **修复 Next.js 代理配置** - 端口从 5001 改为 9000
2. ✅ **添加 CSRF Token 认证** - 解决 401 Unauthorized 问题
3. ✅ **重启前端服务** - 新配置已生效

## 🧪 测试步骤

### 前提条件
确保你已经配置了 FileBay 设置：
1. 点击右上角头像
2. 选择 "设置"
3. 找到 "Gitea 设置" 或 "FileBay 设置"
4. 填写以下信息：
   - Gitea URL (例如: `https://your-filebay-server.com`)
   - Owner (仓库所有者)
   - Repository (仓库名称)
   - Token (访问令牌)
   - Branch (可选，默认 main)

### 测试文件选择器

#### 步骤 1: 打开聊天页面
1. 访问 http://localhost:3000
2. 登录系统
3. 打开任意聊天应用或创建新的聊天

#### 步骤 2: 打开文件选择器
1. 在聊天输入框中，找到文件上传按钮（📎 图标）
2. 点击文件上传按钮
3. 应该会看到 "从 FileBay 选择" 选项
4. 点击 "从 FileBay 选择"

#### 步骤 3: 浏览文件
文件选择器应该显示：
- ✅ 当前路径（顶部显示）
- ✅ 目录列表（文件夹图标）
- ✅ 文件列表（文件图标 + 文件大小）
- ✅ 返回按钮（如果不在根目录）

#### 步骤 4: 导航测试
1. **进入目录**: 点击任意目录，应该显示该目录下的文件
2. **返回上级**: 点击左上角的返回按钮，应该返回上级目录
3. **选择文件**: 点击任意文件，文件应该被高亮选中
4. **确认选择**: 点击 "确认" 按钮，文件应该被上传到聊天

### 预期结果

#### ✅ 成功的表现
- 文件列表正常加载
- 可以进入和退出目录
- 可以选择文件
- 文件成功上传到聊天
- 没有错误提示

#### ❌ 如果出现问题

**问题 1: 仍然显示 500 错误**
- 检查前端是否已重启（应该在 http://localhost:3000）
- 检查后端是否运行在 9000 端口
- 查看浏览器控制台的错误信息

**问题 2: 显示 401 Unauthorized**
- 确认你已经登录系统
- 清除浏览器缓存和 cookies
- 重新登录

**问题 3: 显示 "Missing required FileBay credentials"**
- 检查 FileBay 配置是否完整
- 确认所有必填字段都已填写
- Token 是否有效

**问题 4: 文件列表为空**
- 检查 FileBay 仓库是否有文件
- 检查 Token 是否有读取权限
- 查看后端日志是否有错误

## 🔍 调试信息

### 查看浏览器控制台
1. 按 F12 打开开发者工具
2. 切换到 "Console" 标签
3. 查看是否有错误信息

### 查看网络请求
1. 在开发者工具中切换到 "Network" 标签
2. 打开文件选择器
3. 查找 `/console/api/filebay/list-files` 请求
4. 检查：
   - 状态码应该是 200
   - 响应应该包含文件列表
   - 请求头应该包含 `X-CSRF-Token`

### 查看后端日志
后端日志应该显示：
```
[FileBay API] ===== LIST FILES REQUEST =====
[FileBay API] Path: /
[FileBay API] User: your-email@example.com
[FileBay API] Config - url: https://..., owner: ..., repo: ..., branch: main
[FileBay API] Listing files in path: /
[FileBay API] Found X directories and Y files
```

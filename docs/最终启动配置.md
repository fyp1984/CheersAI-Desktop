## ⚠️ 重要变更

### API 端口变更：5001 → 9000

由于 Windows socket 权限问题（WinError 10013），API 无法绑定到端口 5001。

**解决方案**：使用端口 9000

**原因分析**：
- 端口 5001 可能被 Windows 系统或安全软件限制
- 端口 9000 可以正常绑定
- 使用 Waitress WSGI 服务器（Windows 兼容）

### 前端配置需要更新

前端需要连接到新的 API 端口：

**修改文件**：`web/.env` 或 `web/.env.local`

```env
# 旧配置
NEXT_PUBLIC_API_URL=http://localhost:5001

# 新配置
NEXT_PUBLIC_API_URL=http://localhost:9000
```

或者在代码中查找所有 `5001` 的引用并改为 `9000`。

## 🔍 故障排除

### 如果 API 无法启动

**问题**：端口权限错误（WinError 10013）

**解决方案**：
1. 尝试其他端口（如 9000, 9001, 8000）
2. 以管理员身份运行 PowerShell
3. 检查防火墙设置
4. 检查端口是否被占用：`netstat -ano | findstr :9000`

### 如果前端无法连接 API

**问题**：前端配置指向错误的端口

**解决方案**：
1. 检查 `web/.env` 或 `web/.env.local`
2. 确保 `NEXT_PUBLIC_API_URL=http://localhost:9000`
3. 重启前端服务

### 如果 Docker 服务无法启动

**问题**：端口冲突或容器已存在

**解决方案**：
```bash
# 停止所有容器
docker-compose -f docker-compose.dev.yaml down

# 重新启动
docker-compose -f docker-compose.dev.yaml up -d

# 检查状态
docker ps
```

### 如果 Plugin Daemon 无法连接

**问题**：端口配置错误

**解决方案**：
1. 确认端口是 5012-5013（不是 5002-5003）
2. 检查 `docker-compose.dev.yaml` 配置
3. 检查 `api/.env` 中的 PLUGIN_DAEMON_URL
4. 重启 Plugin Daemon 容器

# 插件签名验证问题解决方案

## 🔧 问题描述

错误信息：
```
PluginDaemonBadRequestError: plugin verification has been enabled, 
and the plugin you want to install has a bad signature
```

## ✅ 已解决

### 问题原因
Dify 的 Plugin Daemon 启用了插件签名验证，但我们的自定义插件没有官方签名。

### 解决方案
在开发环境中禁用插件签名验证。

## 📝 已修改的配置

### 1. API 环境配置 (`api/.env`)

添加了：
```env
# Plugin Signature Verification (disable for development)
PLUGIN_SIGNATURE_VERIFICATION_ENABLED=false
```

### 2. Plugin Daemon 配置 (`docker-compose.dev.yaml`)

在 `plugin_daemon` 服务的环境变量中添加了：
```yaml
SIGNATURE_VERIFICATION_ENABLED: 'false'
```

### 3. 服务重启

- ✅ API 服务已重启
- ✅ Plugin Daemon 容器已重启

## ⚠️ 重要说明

### 开发环境 vs 生产环境

**开发环境**（当前配置）:
- ✅ 禁用签名验证
- ✅ 可以安装自定义插件
- ✅ 适合开发和测试

**生产环境**（建议配置）:
- ⚠️ 启用签名验证
- ⚠️ 只能安装官方签名的插件
- ⚠️ 更安全，但限制更多

### 如何在生产环境使用

如果需要在生产环境使用自定义插件，有以下选项：

#### 选项 1: 使用远程调试模式
```bash
# 在插件目录配置 .env
INSTALL_METHOD=remote
REMOTE_INSTALL_URL=your-dify-instance:5003
REMOTE_INSTALL_KEY=your-debug-key

# 运行插件
python -m main
```

#### 选项 2: 申请官方签名
- 将插件提交到 Dify 官方仓库
- 通过审核后获得官方签名
- 发布到 Dify Marketplace

#### 选项 3: 自签名（高级）
- 生成自己的签名密钥
- 配置 Plugin Daemon 信任你的密钥
- 对插件进行签名

## ❓ 常见问题

### Q1: 修改配置后还是报签名错误？

**A**: 
1. 确认 Plugin Daemon 容器已重启
2. 确认 API 服务已重启
3. 清除浏览器缓存
4. 重新上传插件

### Q2: 如何恢复签名验证？

**A**: 
1. 从 `docker-compose.dev.yaml` 中删除 `SIGNATURE_VERIFICATION_ENABLED: 'false'`
2. 从 `api/.env` 中删除 `PLUGIN_SIGNATURE_VERIFICATION_ENABLED=false`
3. 重启服务

### Q3: 禁用签名验证安全吗？

**A**: 
- 在开发环境中是安全的
- 在生产环境中不推荐
- 只安装你信任的插件

### Q4: 其他插件也需要这样配置吗？

**A**: 
- 官方插件不需要
- 自定义插件都需要
- 一次配置，所有自定义插件都可用
